This document defines the SaaS tier model for AI JOKER-C2.

The model is designed to transfer JOKER-C2 from an HBCE R&D governed prototype into a SaaS Core v0.1 service with progressive access levels, verified IPR identity, model escalation, memory scope, EVT continuity, OPC technical proof receipts, dashboard audit visibility and a restricted C2 Defense perimeter.

---

## 2. Core principle

Classic AI SaaS products usually scale by usage, seats, tokens or access to a larger model.

JOKER-C2 scales by operational value.

The pricing and access model must evaluate:

```text
verified IPR identity
SaaS tier
operational context
risk level
model level
memory scope
audit requirement
EVT requirement
OPC requirement
cyber boundary
organization or workspace status
commercial value of the response

Canonical principle:

The cost grows with the operational value of the response,
not only with the number of tokens consumed.

Short commercial formula:

Pay for governed operational value, not only for raw AI usage.

HBCE formula:

IPR enables.
JOKER-C2 responds.
MATRIX organizes.
Memory preserves continuity.
EVT traces.
OPC proves.
HBCE governs.

3. Tier list

The SaaS model includes six tiers:

BASE
IPR
PRO
GOVERNANCE
C2_DEFENSE

These tiers are not only commercial labels.

They define runtime permissions, model routing, memory behavior, audit depth, event generation, proof generation and cyber boundaries.

5. BASE tier

BASE is the entry tier for exploratory or non-verified users.

BASE allows limited interaction with JOKER-C2 without granting operational identity, persistent memory, high-value audit or cyber capabilities.

Target users

exploratory visitors
early demo users
non-verified users
low-risk informational users

Access

IPR status: NOT_VERIFIED or LIMITED
identity binding: none or runtime-only
certificate: not required
organization: not required
workspace: not required

Runtime behavior

model level: STANDARD
memory scope: RUNTIME_ONLY
EVT: minimal or optional
OPC: disabled or minimal
dashboard: limited
risk: low only
cyber: general educational explanation only

Allowed use cases

general questions
basic explanation of HBCE concepts
basic explanation of IPR, EVT, OPC and MATRIX
non-sensitive writing support
public documentation navigation
low-risk product discovery

Restricted use cases

IPR-bound memory
workspace audit
proof-bearing reports
organization-level governance
C2 Defense
high-risk cyber operations
sensitive operational decisions

Boundary statement

BASE is an exploratory access tier.
BASE does not provide operational identity, persistent memory, governed audit depth or C2 Defense access.

memory scope: IPR_BOUND
EVT: enabled
OPC: optional or enabled

risk: low to medium
cyber: general defensive guidance only unless separately authorized

Allowed use cases

IPR-bound continuity
personal operational memory
project planning

governed AI assistance
technical explanations
audit-aware individual workflows

Restricted use cases

organization governance without workspace
mandatory legal proof claims
public authority identity claims

high-risk cyber operations

IPR tier converts a generic user into a verified operational subject inside JOKER-C2.
The runtime must identify the subject through server-side IPR state, not prompt declaration.

cyber: authorized defensive use only

Allowed use cases

defensive hardening

Boundary statement

C2 is not a premium subscription.
C2 is a governed defensive operational perimeter.

17. Upgrade logic

Tier upgrade must be based on capability need and authorization.

BASE → IPR
requires verified IPR identity

IPR → PRO
requires professional workflow activation

PRO → GOVERNANCE
requires organization or workspace

GOVERNANCE → C2_DEFENSE
requires verified organization, authorized defensive perimeter and cyber policy approval

GOVERNANCE → STRATEGIC
requires pilot or contract

C2_DEFENSE → STRATEGIC
requires dedicated pilot, contract or critical operational context

Upgrade must not be framed only as payment.

Some tiers require verification and authorization.

Boundary:

Payment alone does not grant C2 Defense access.
Payment alone does not grant Strategic access.
Authorization, perimeter and governance are required.


---

18. Downgrade and limitation logic

The runtime must be able to reduce access.

Downgrade or limitation may occur when:

IPR verification is missing
certificate is inactive
organization is not verified
workspace is inactive
billing status is inactive
risk is unresolved
cyber perimeter is unclear
request exceeds tier
request violates policy
database is unavailable
runtime health is degraded

Possible downgrade states:

FULL_ACCESS
LIMITED_ACCESS
RUNTIME_ONLY
AUDIT_ONLY
BLOCKED
FAIL_CLOSED

Required behavior:

If identity cannot be verified, reduce to BASE or LIMITED.
If organization cannot be verified, block GOVERNANCE or C2 features.
If C2 perimeter cannot be resolved, fail closed.
If database is unavailable, declare MVP boundary.
If model is unavailable, fallback only within safe policy.
