7. SaaS tier model

The SaaS model scales by operational value, not only by token usage.

The planned SaaS levels are:

Tier	Target	Access	Main value

BASE	Exploratory users	Limited access	Governed basic AI interaction
IPR	Verified individuals	IPR verified access	IPR-bound continuity and memory
PRO	Professionals and small teams	IPR + professional workflows	Reports, documents, audit-oriented work
GOVERNANCE	Companies and institutions	Workspace and roles	Policy, responsibility, audit and process traceability
C2_DEFENSE	Authorized cyber teams	Verified organization and authorized perimeter	Defensive cyber support under mandatory audit
STRATEGIC	B2B / B2G / critical contexts	Contractual or pilot access	Dedicated governed runtime and strategic continuity


Canonical pricing principle:

The cost grows with the operational value of the response,
not only with the number of tokens consumed.

8. Model escalation principle

JOKER-C2 must include a model escalation layer.

The base model remains available for ordinary, low-risk and low-cost responses. More advanced models are activated only when justified by IPR status, SaaS tier, domain, risk, complexity, value and audit requirements.

Canonical logic:

BASE request
→ standard model

IPR verified request
→ enhanced governed model

PRO or GOVERNANCE request
→ advanced model with EVT/OPC support

Authorized C2 Defense request
→ C2 escalation with mandatory audit

Unauthorized or unclear cyber request
→ fail-closed

The system must be able to explain why a model level was selected.

The selected model level must be traceable in EVT and OPC records whenever the request has operational value.


---

9. Memory principle

JOKER-C2 memory is not generic chat history.

The memory layer is IPR-bound operational continuity.

Minimum memory states:

RUNTIME_ONLY
PROCESS_MEMORY_MVP
IPR_BOUND
WORKSPACE_BOUND
DATABASE_PERSISTENT

During the transition phase, the runtime may still operate with PROCESS_MEMORY_MVP, but the boundary must remain explicit.

If persistent storage is not configured:

Persistence mode: PROCESS_MEMORY_MVP
Boundary: non-persistent serverless memory

If persistent storage is configured:

Persistence mode: DATABASE_PERSISTENT
Boundary: operational persistence enabled

The roadmap objective is to prepare the transition from process memory to database-backed IPR-bound memory.
